## 1. 交付方式与系统要求

### 1.1 标准交付物

从 GitHub Release `v1.0.0` 下载 `smokefire-deploy-1.0.0-cpu.zip`。该包已经包含：

- 预构建的 smokefire CPU Docker 镜像；
- `fire_smoke_v5.pt` 与 `smoking_v4.pt` 两个模型权重；
- Docker Compose 配置；
- Windows / Linux 启停脚本；
- 中英文部署、操作和模型实测 PDF；
- SHA-256 校验清单。

部署包不包含项目源码。目标机不需要 Python、Git 或编译工具；首次安装完成后，系统运行也不依赖 GitHub。

### 1.2 主机要求

| 项目 | 最低建议 | 说明 |
|---|---|---|
| CPU | x86_64，4 核 | 路数增加时需实测；CPU 包适合试点或小规模部署 |
| 内存 | 8 GB | 建议 16 GB 或更高 |
| 磁盘 | 20 GB 可用空间 | 还需另计事件录像、快照和备份空间 |
| Docker | Docker Engine / Desktop 24+ | 必须带 Docker Compose v2 |
| 浏览器 | 当前维护版本的 Chrome / Edge | 用于操作界面 |
| 摄像头 | RTSP，推荐 H.264 | 目标机必须能访问摄像头或 NVR |

标准包为 CPU 版本。多路生产部署应在目标主机用真实码流验证吞吐、延迟和稳定性；需要 GPU 版本时，应获取与显卡驱动和 CUDA 环境匹配的独立交付包。

## 2. 下载与校验

### 2.1 下载

项目地址：

```text
https://github.com/newtv-ai/smokefire
```

进入 Releases，选择 `v1.0.0`，下载：

```text
smokefire-deploy-1.0.0-cpu.zip
```

### 2.2 解压

Windows 建议解压到不含中文和空格的目录，例如：

```text
D:\smokefire
```

Linux 示例：

```bash
sudo mkdir -p /opt/smokefire
sudo unzip smokefire-deploy-1.0.0-cpu.zip -d /opt/smokefire
cd /opt/smokefire
```

### 2.3 校验交付物

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\verify.ps1
```

Linux：

```bash
chmod +x verify.sh start.sh stop.sh
./verify.sh
```

两个模型的固定校验值：

| 文件 | 大小 | SHA-256 |
|---|---:|---|
| `models/fire_smoke_v5.pt` | 44,014,233 字节 | `b5248d55c5d90e341bc4e537887d4bce4b9af1bd0330ddd87825294750a1e216` |
| `models/smoking_v4.pt` | 44,025,689 字节 | `0ea7b66c2105f1898f56f828b18ffb01934fb1f47a795192e8867ae8fcb128dd` |

校验失败时不要继续部署，应重新下载对应文件。

## 3. Windows 部署

### 3.1 安装 Docker Desktop

安装 Docker Desktop 并选择 Linux containers。启动 Docker Desktop，等待状态显示引擎已运行，然后在 PowerShell 验证：

```powershell
docker version
docker compose version
```

两个命令都必须能返回版本信息。

### 3.2 启动

在部署包目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

脚本会校验文件、导入预构建镜像、启动容器，并等待健康检查通过。镜像首次导入会耗时数分钟。

### 3.3 查看状态和日志

```powershell
docker compose ps
docker compose logs -f smokefire
```

按 `Ctrl+C` 只会退出日志查看，不会停止服务。

### 3.4 停止和重启

```powershell
powershell -ExecutionPolicy Bypass -File .\stop.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

停止脚本不会删除事件数据卷。

## 4. Linux 部署

### 4.1 安装 Docker

安装 Docker Engine 与 Compose v2。安装方式以操作系统发行版的官方文档为准。完成后验证：

```bash
docker version
docker compose version
```

若当前用户没有 Docker 权限，可在本章命令前加 `sudo`，或由管理员配置 Docker 用户组后重新登录。

### 4.2 启动

```bash
cd /opt/smokefire
chmod +x verify.sh start.sh stop.sh
./start.sh
```

### 4.3 查看状态和日志

```bash
docker compose ps
docker compose logs -f smokefire
```

### 4.4 停止和重启

```bash
./stop.sh
./start.sh
```

Docker 的 `restart: unless-stopped` 策略会在主机重启、Docker 服务恢复后自动拉起容器；首次投产前应做一次主机重启验证。

## 5. 首次启动与验收

### 5.1 打开系统

在服务主机浏览器打开：

```text
http://127.0.0.1:8600
```

首次启动加载两个模型可能需要数十秒至数分钟。

### 5.2 健康检查

| 地址 | 用途 | 期望结果 |
|---|---|---|
| `/api/health/live` | 进程是否存活 | HTTP 200 |
| `/api/health/ready` | 模型、调度、录像和磁盘是否就绪 | HTTP 200 |
| `/api/status` | 运行指标和通知统计 | 返回 JSON |

示例：

```bash
curl http://127.0.0.1:8600/api/health/live
curl http://127.0.0.1:8600/api/health/ready
```

### 5.3 最小验收

1. 浏览器可打开预览墙、事件中心和摄像头管理。
2. 添加一条授权使用的真实 RTSP 摄像头。
3. 摄像头最终显示“在线”，预览画面和名称正确。
4. 使用授权测试素材或现场可控方式触发一次告警。
5. 事件中心能看到快照、类别、置信度、时间和录像。
6. 分别验证“确认属实”和“标记误报”。
7. 重启服务后摄像头配置和历史事件仍在。

部署成功不等于正式验收完成。正式项目还要在真实网络、磁盘和计划路数下验证容量、延迟、误报、漏报、录像完整性、断流恢复和连续运行稳定性。

## 6. 摄像头接入准备

部署前准备：摄像头名称、RTSP 地址、账号密码、NVR 网段、编码格式、分辨率、码率和计划路数。

先在服务主机验证网络：

```powershell
Test-NetConnection <摄像头IP> -Port 554
```

Linux：

```bash
nc -vz <摄像头IP> 554
```

RTSP 地址示例：

```text
rtsp://user:password@192.168.1.20:554/stream1
```

建议优先使用 H.264 主码流或适合算力的子码流。H.265、超高分辨率、过高码率或厂商私有封装应在现场单独验证。

## 7. 配置与局域网访问

部署包默认只把 Web 端口绑定到 `127.0.0.1:8600`。如需从局域网其他电脑访问，由实施人员在 `docker-compose.yml` 中把端口绑定改为指定的内网 IP，并在 `.env` 中设置允许的访问主机名，然后重启服务。

常用配置位于 `.env`：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `SMOKEFIRE_ALLOWED_HOSTS` | `localhost,127.0.0.1` | 允许访问 Web 的 Host |
| `SMOKEFIRE_WEBHOOK_URL` | 空 | 全局 webhook 地址 |
| `SMOKEFIRE_INFER_WORKERS` | `4` | CPU 推理 worker 数 |
| `SMOKEFIRE_INFER_BATCH_MAX` | `8` | 最大推理批次 |
| `SMOKEFIRE_STOP_GRACE_PERIOD` | `180s` | 停机宽限时间 |

全局环境变量修改后执行停止、启动脚本。逐路检测参数在摄像头管理页面保存后热生效。

摄像头凭据可能出现在 RTSP 地址中。限制部署目录、备份和终端历史的访问范围，交付截图和工单中不要暴露完整凭据。

## 8. 日常运维

每日建议检查：

```bash
docker compose ps
docker compose logs --tail 200 smokefire
curl http://127.0.0.1:8600/api/health/ready
```

同时在界面确认摄像头在线、预览更新、最新事件可回放、磁盘没有达到高水位。不要使用 `docker compose down -v`，该命令会删除命名卷中的业务数据。

## 9. 备份、恢复与升级

### 9.1 备份

业务数据存放在 `smokefire-data` 命名卷。备份前建议停止服务，记录当前版本，并使用管理员认可的 Docker 卷备份方法复制整个 `/app/data` 内容。

备份至少应覆盖：摄像头配置、SQLite 数据库、事件录像、快照、误报反馈和通知队列。只复制数据库但不复制证据文件不是完整备份。

### 9.2 恢复

1. 停止服务。
2. 恢复同一版本对应的完整数据目录。
3. 启动服务。
4. 验证健康检查、摄像头、历史事件、录像和反馈数据。

### 9.3 升级

1. 备份数据卷并验证备份可读。
2. 下载并校验新版本部署包。
3. 停止旧版本，在新目录运行启动脚本。
4. 执行健康检查和最小业务验收。
5. 出现异常时停止新版本，恢复旧镜像和升级前备份。

## 10. 故障排查

| 现象 | 优先检查 | 处理建议 |
|---|---|---|
| Docker 命令不可用 | Docker Desktop / Engine 是否启动 | 启动引擎后重试 `docker version` |
| 启动时报镜像文件缺失 | `images/` 目录与压缩包是否完整 | 重新下载并运行校验脚本 |
| `ready` 长时间不通过 | 容器日志、模型校验、磁盘空间 | `docker compose logs --tail 300 smokefire` |
| 网页打不开 | 容器状态、8600 端口、绑定地址 | 先在服务主机访问 `127.0.0.1` |
| 摄像头一直重连 | RTSP、账号密码、554 端口、编码 | 用播放器在同一主机验证同一 RTSP |
| 预览黑屏但显示在线 | 浏览器解码、网络抖动、首段录像 | 刷新并检查日志和码流格式 |
| 没有告警 | 能力开关、阈值、画面目标大小 | 用授权正样本验证，不要直接大幅降阈值 |
| 告警过多 | 蒸汽、雾气、反光、进食等干扰 | 收集误报并用同一批正负样本调参 |
| 事件没有录像 | 磁盘、录像预热、源流稳定性 | 检查磁盘状态和 FFmpeg 日志 |
| 磁盘接近满 | 事件保留和备份策略 | 先备份，再在存储管理中按时间清理 |
